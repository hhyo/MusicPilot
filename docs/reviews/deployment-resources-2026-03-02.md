## 1. 项目需求分析

### 1.1 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| **后端** | FastAPI + SQLAlchemy | Python 3.10+, ASGI |
| **前端** | Vue 3 + Vite + Naive UI | 静态资源部署 |
| **数据库** | SQLite → PostgreSQL | 开发用 SQLite，生产用 PostgreSQL |
| **后台任务** | APScheduler | 定时任务（订阅检查等）|
| **存储** | 本地文件系统 | 音乐文件存储（可选）|

### 1.2 部署需求

- **后端服务**: 长运行 Web Service (FastAPI)
- **前端服务**: 静态站点托管
- **数据库**: PostgreSQL（免费层可接受 1GB）
- **后台任务**: 需要 Worker 支持（可选）

## 2. 平台对比分析

### 2.1 免费层对比

| 平台 | 免费层 | Web Service | PostgreSQL | Background Worker | 休眠 | 商业使用 |
|------|--------|-------------|------------|-------------------|------|----------|
| **Render** | ✅ 永久免费 | ✅ 750h/月 | ✅ 1GB | ❌ 需付费 | 15分钟无请求 | ✅ 允许 |
| **Railway** | ⚠️ 试用 $5 额度 | ✅ | ✅ | ✅ | 可配置 | ✅ 允许 |
| **Fly.io** | ❌ 无免费层 | ✅ | ✅ | ✅ | 可配置 | ✅ 允许 |
| **Vercel** | ✅ 永久免费 | ⚠️ Serverless | ❌ 需外部 | ❌ | 冷启动 | ✅ 允许 |

### 2.2 详细分析

#### Render（推荐）

**优点**：
- ✅ 真正免费，无需信用卡，永久有效
- ✅ 750 小时/月 Web Service（足够运行 1 个服务）
- ✅ 免费 1GB PostgreSQL 数据库
- ✅ 免费静态站点托管（前端）
- ✅ GitHub 集成，自动部署
- ✅ SSL/CDN 内置

**缺点**：
- ❌ Background Worker 不在免费层
- ❌ 服务休眠（15分钟无请求，首次访问需等待）
- ❌ 有限的 CPU/RAM（0.1 CPU, 512MB RAM）

**适用场景**：演示、测试、小型项目

#### Railway

**优点**：
- ✅ 开发体验最佳，Dashboard 直观
- ✅ 快速部署，模板丰富
- ✅ 支持 Background Worker
- ✅ PostgreSQL 内置
- ✅ 实时日志和指标

**缺点**：
- ❌ 无永久免费层，试用后最低 $5/月
- ❌ 按使用计费，需关注成本

**适用场景**：快速原型、初创项目

#### Fly.io

**优点**：
- ✅ 全球多区域部署
- ✅ 低延迟，适合 WebSocket
- ✅ 完整容器支持
- ✅ PostgreSQL 高可用

**缺点**：
- ❌ 无免费层，按使用计费
- ❌ 需要 DevOps 技能
- ❌ CLI 为主，学习曲线

**适用场景**：生产环境、全球用户

#### Vercel

**优点**：
- ✅ 前端部署最佳
- ✅ 全球 CDN
- ✅ 预览部署
- ✅ 免费层慷慨

**缺点**：
- ❌ Python 支持 Serverless only（冷启动）
- ❌ 无内置数据库
- ❌ 不适合长运行后台任务

**适用场景**：前端为主，轻量 API

## 4. 部署步骤（方案A：Render）

### 4.1 前置准备

1. 确保项目有 `render.yaml` 配置文件
2. 确保 `Dockerfile` 存在且可用
3. 准备环境变量列表

### 4.2 部署步骤

1. 注册 Render 账号（可用 GitHub 登录）
2. 创建 PostgreSQL 数据库（免费 1GB）
3. 创建 Web Service（后端）
   - 连接 GitHub 仓库
   - 选择分支
   - 配置环境变量
4. 创建静态站点（前端）
   - 构建命令：`npm run build`
   - 输出目录：`dist`

### 4.3 定时任务替代方案

由于 Render 免费层不支持 Background Worker，采用以下替代方案：

**方案1：外部 Cron 服务**
- 使用 cron-job.org（免费）
- 定时调用 API 触发任务

**方案2：GitHub Actions**
- 使用 `schedule` 触发器
- 调用部署的 API 端点
