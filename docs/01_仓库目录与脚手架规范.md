# 01. 仓库目录与脚手架规范

## 1.1 目标
本仓库采用“源码工程目录 + 发布产物目录”双层结构：

- 源码工程目录服务于日常开发、联调、测试、文档维护
- 发布产物目录服务于 MoviePilot 插件加载与发版
- 构建阶段统一完成目录映射，不在运行时动态拼目录

## 1.2 开发目录（固定）
```text
musicpilot/
  frontend/
  backend/
  docs/
  scripts/
  plugin_runtime/
```

## 1.3 目录职责

### frontend/
独立前端工程。负责：
- 插件入口壳
- 榜单、搜索、订阅、下载、整理、设置页面
- 领域组件与状态管理
- 打包后输出到 plugin_runtime/static/

建议结构：
```text
frontend/
  package.json
  tsconfig.json
  vite.config.ts
  src/
    main.ts
    App.vue
    router/
    stores/
    api/
    types/
    pages/
    components/
  public/
```

### backend/
独立后端工程。负责：
- 插件 API
- 业务服务与领域模型
- 数据访问与迁移
- 与宿主 PT/下载器/通知/调度能力的适配

建议结构：
```text
backend/
  pyproject.toml
  app/
    main.py
    core/
    api/
    models/
    schemas/
    services/
    repositories/
    adapters/
    tasks/
  migrations/
  tests/
```

### docs/
项目文档：
- 顶层设计
- 落地实施方案
- API 契约
- 探针验证记录
- 联调与发版说明

### scripts/
工程脚本：
- 本地开发启动
- 前端构建
- 后端打包
- 版本同步
- 产物装配
- 发布打包

### plugin_runtime/
面向 MoviePilot 的最终插件产物目录模板。构建后至少应包含：
```text
plugin_runtime/
  package.json
  plugins/
    musicpilot/
      __init__.py
      requirements.txt
      api/
      services/
      models/
      static/
```

## 1.4 开发目录 -> 发布目录映射
```text
frontend/dist                -> plugin_runtime/plugins/musicpilot/static/
backend/app/**               -> plugin_runtime/plugins/musicpilot/
backend/requirements.txt     -> plugin_runtime/plugins/musicpilot/requirements.txt
scripts/sync_version.py      -> 构建阶段执行，不进入产物
根目录元数据                -> plugin_runtime/package.json
```

## 1.5 根目录约定
源码仓库根目录建议至少包含：
```text
musicpilot/
  README.md
  .gitignore
  .editorconfig
  .env.example
  frontend/
  backend/
  docs/
  scripts/
  plugin_runtime/
```

## 1.6 Codex 开工要求
Codex 第一轮必须完成：
1. 初始化上述目录
2. 前后端脚手架可本地启动
3. plugin_runtime 中有标准插件占位结构
4. scripts 具备 build/package 最小链路
5. README 明确开发与打包命令

## 1.7 非目标
- 不把源码仓库直接做成官方插件仓库形态
- 不在运行时临时推断插件目录
- 不在 frontend 和 backend 中混放发布产物
