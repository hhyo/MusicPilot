# 02. 技术选型冻结

## 2.1 总原则
- 选型以“尽快落地 + 易于 Codex 生成 + 便于与 MoviePilot 宿主对接”为优先
- V1 不引入额外分布式中间件
- 先保证插件闭环，再考虑扩展性重构

## 2.2 前端选型（冻结）
- **框架**：Vue 3
- **语言**：TypeScript
- **构建工具**：Vite 5
- **路由**：Vue Router 4
- **状态管理**：Pinia
- **HTTP Client**：Axios
- **UI 组件**：Element Plus
- **样式方案**：SCSS + CSS Variables
- **测试**：Vitest + Vue Test Utils
- **E2E**：Playwright（Phase 4 再补）

### 选择理由
1. 组件化与状态管理成熟，适合多页插件工程
2. 与现有 Vue 生态、远程前端接入方式兼容性更好
3. Codex 对 Vue 3 + TS + Vite 生成效率高

## 2.3 后端选型（冻结）
- **语言**：Python 3.12
- **Web 框架**：FastAPI
- **数据校验**：Pydantic v2
- **ORM**：SQLAlchemy 2.x
- **迁移工具**：Alembic
- **HTTP Client**：httpx
- **序列化**：orjson
- **测试**：pytest
- **日志**：structlog 或标准 logging + JSON formatter

### 选择理由
1. 与插件生态和现有 Python 业务逻辑适配度高
2. FastAPI 适合快速定义清晰 API 契约
3. SQLAlchemy + Alembic 便于 Codex 按模型生成迁移

## 2.4 数据存储（冻结）
- **开发环境**：SQLite
- **生产推荐**：PostgreSQL
- **缓存策略**：V1 先用数据库 + 进程内缓存，不引入 Redis
- **任务状态**：数据库持久化，调度仍由宿主 service 驱动

## 2.5 工程工具（冻结）
- **Node 包管理**：pnpm
- **Python 环境**：venv + pip
- **代码格式化**：
  - frontend: eslint + prettier
  - backend: ruff + black
- **CI**：GitHub Actions
- **版本策略**：语义化版本（SemVer）

## 2.6 发布策略（冻结）
- 开发仓库与运行产物分离
- 构建脚本输出标准插件目录到 `plugin_runtime/`
- 不直接把 frontend/backend 原始源码作为宿主可加载目录
- 版本号需在以下位置同步：
  - `frontend/package.json`
  - `backend/pyproject.toml`
  - `plugin_runtime/package.json`
  - `plugins/musicpilot/__init__.py` 中的版本常量

## 2.7 MVP 明确不做
- 微服务拆分
- 独立消息队列
- Redis 级缓存
- 跨节点分布式任务执行
- 全量 AI 推荐系统
