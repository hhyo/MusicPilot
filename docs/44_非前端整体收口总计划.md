# 非前端整体收口总计划

> 状态：2026-04-13 制定。本文覆盖除前端重写之外的剩余非前端目标，用作统一执行与验收基线。

## 1. 结论

当前已经完成的部分：

- 统一音乐媒体解析链
- metadata / charts / jobs / downloads / organize / subscriptions / settings / dashboard 主业务 API
- plugin runtime backend mirror
- 基础测试、打包、README / backend README 主说明

如果按最终产品目标“发现 -> 识别 -> 获取 -> 下载 -> 整理 -> 订阅自动化 -> 宿主联调可信交付”衡量，**除前端外仍未全部完成**。

当前剩余的非前端工作集中在以下 3 个产品化里程碑：

1. 获取链路产品化与工作台收口
2. 下载完成后的自动闭环
3. 宿主能力验证与运行态观测收口

## 2. 本计划的范围

### 2.1 在范围内

- QueryBuilder、SearchJob、dispatch、downloads workspace 的产品化补齐
- path handoff、下载完成回填、自动 organize / apply 的闭环收口
- host probe / validation / diagnostics 的真实化收口
- dashboard 与运行态观测增强
- 文档、测试、runtime mirror、打包与运行态验证

### 2.2 不在范围内

- 前端视觉、页面结构、组件体系重写
- 宿主 MoviePilot / MoviePilot-Frontend 代码改造
- 数据库体系重构或引入消息队列、中间件基础设施

## 3. 最终完成定义

只有同时满足以下条件，才可认为“除前端外，整体目标达成”：

1. 统一音乐媒体解析链不再有待收口的主路径问题。
2. QueryBuilder / SearchJob / dispatch / downloads workspace / organize / subscription execution 串成稳定的后端业务闭环。
3. 下载完成后的 path handoff、自动 organize preview、自动 apply 具备明确状态机和恢复动作。
4. probe 不再只是大量占位壳层，而形成真实宿主能力结论与诊断输出。
5. dashboard 能表达 provider、discovery、search、downloads、handoff、organize、scheduler 的真实状态。
6. README、backend README、路线文档与运行态文档都能如实反映当前状态。
7. backend 全量测试、关键定向测试、plugin_runtime 打包、必要的真实运行态验证全部通过。

## 4. 剩余问题总表

### 4.1 获取链路问题

- `backend/app/services/query_builder.py`
  - 当前仍需要进一步增强工作台层的解释性与决策输出
- `backend/app/services/metadata.py`
  - detail 仍主要停留在 metadata 结果，不包含获取、派发、整理上下文

### 4.2 下载闭环问题

- `backend/app/services/downloads_workspace.py`
  - 已有 bindings/tasks/retry 动作，但还缺 task 级生命周期增强、handoff 恢复策略收口
- `backend/app/services/pending_handoff.py`
  - 已有自动续跑，但需要与下载工作台、scheduler、diagnostics 更紧密耦合

### 4.3 宿主验证问题

- `backend/app/api/routes/probe.py`
- `backend/app/adapters/host_probe.py`
  - 仍需要进一步收紧真实宿主能力结论

### 4.4 交付与可观测性问题

- `backend/app/services/dashboard.py`
  - 已是聚合接口，但仍需要更细的诊断维度
- 文档需要继续保持与当前完成态一致

## 5. 一次性并行工作流

### Workstream A：SearchJob / Candidate / Dispatch / Downloads Workspace 完整化

**目标**

- 把获取工作台真正做成可管理业务面，而不是只停在单次执行。

### Workstream B：下载完成后的自动闭环

**目标**

- 把 `dispatch -> handoff -> organize preview/apply` 收成真正稳定的自动链路。

### Workstream C：Host Probe / Validation / Diagnostics 收口

**目标**

- 让 probe 成为真实可用的宿主能力验证层。

### Workstream D：Dashboard / 运行态观测 / 文档真相

**目标**

- 让后端真正可观测、可交付，而不是只能跑通。

## 6. 执行方式

本计划按独立 worktree 并行推进多个工作流，最后统一回到主线完成验证与文档同步。

## 7. 验收矩阵

- backend 全量测试
- plugin runtime 打包
- 关键定向验证
- 必要的真实运行态验证
