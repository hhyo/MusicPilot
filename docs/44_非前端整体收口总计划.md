# 非前端整体收口总计划

> 状态：2026-04-13 更新。本文只保留当前仍有效的非前端收口目标，用作统一执行与验收基线。

## 1. 当前结论

截至当前版本，以下部分已经可以视为主干完成：

- 统一音乐媒体解析链：`MusicMediaInput -> MusicMetaBase -> MusicMediaInfo`
- metadata / charts / jobs / downloads / organize / subscriptions / settings / dashboard 主业务 API
- `charts` / `chart_items` 持久化与统一 `music-chart-refresh` 周期刷新
- plugin runtime backend mirror
- 基础测试、打包、README / backend README 主说明

按最终产品目标衡量，除前端外仍剩两类非前端收口工作：

1. 下载完成后的自动闭环
2. 宿主能力验证与运行态观测收口

## 2. 范围

### 2.1 在范围内

- path handoff、下载完成回填、自动 organize / apply 的闭环收口
- host probe / validation / diagnostics 的真实化收口
- dashboard 与运行态观测增强
- 文档、测试、runtime mirror、打包与运行态验证

### 2.2 不在范围内

- 前端视觉、页面结构、组件体系重写
- 新榜单源
- 宿主 MoviePilot / MoviePilot-Frontend 代码改造
- 数据库体系重构或引入消息队列、中间件基础设施

## 3. 最终完成定义

只有同时满足以下条件，才可认为“除前端外，整体目标达成”：

1. 下载完成后的 path handoff、自动 organize preview、自动 apply 具备明确状态机和恢复动作。
2. probe 形成真实宿主能力结论与诊断输出，而不是占位解释接口。
3. dashboard 能表达 discovery、downloads、handoff、organize、scheduler 的真实状态。
4. README、backend README、路线文档与运行态文档都能如实反映当前状态。
5. backend 全量测试、关键定向测试、plugin_runtime 打包、必要的真实运行态验证全部通过。

## 4. 剩余问题总表

- `backend/app/services/downloads_workspace.py`
  - 还需要继续收紧 task 生命周期、handoff 恢复动作与诊断表达

  - 还需要与下载工作台、scheduler、dashboard 更紧密耦合

### 4.2 宿主验证问题

- `backend/app/api/routes/probe.py`
- `backend/app/adapters/host_probe.py`
  - 仍需要继续收紧真实宿主能力结论与字段映射

### 4.3 交付与可观测性问题

- `backend/app/services/dashboard.py`
  - 已是聚合接口，但仍需要更细的诊断维度
- 文档需要继续保持与当前完成态一致

## 5. 工作流

### Workstream A：下载完成后的自动闭环

目标：
- 把 `dispatch -> handoff -> organize preview/apply` 收成稳定自动链路。

### Workstream B：Host Probe / Validation / Diagnostics 收口

目标：
- 让 probe 成为真实可用的宿主能力验证层。

### Workstream C：Dashboard / 运行态观测 / 文档真相

目标：
- 让后端真正可观测、可交付，而不是只能跑通。

## 6. 验收矩阵

- backend 全量测试
- plugin_runtime 打包
- 关键定向验证
- 必要的真实运行态验证
