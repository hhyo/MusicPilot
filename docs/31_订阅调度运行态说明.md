# 31 订阅调度运行态说明

## 当前状态

MusicPilot 当前已具备最小应用内订阅调度能力：

- 订阅可使用 `manual` 或 `scheduled` 模式
- 调度器运行在 FastAPI 应用生命周期内
- 调度触发后仍沿用现有同步执行链：
  - metadata detail
  - SearchJob
  - 对最佳 `AUTO_DOWNLOAD` 候选自动 dispatch
  - organize preview
  - 若 preview 已具备明确本地源文件，则继续自动 apply

这不是 production 级 scheduler。

当前仍未包含：

- cron 级表达式
- 分布式任务系统
- 失败重试
- 去重与幂等控制
- 自动下载完成回调与自动 apply

## 配置项

后端新增以下配置：

- `MUSICPILOT_SUBSCRIPTION_SCHEDULER_ENABLED`
- `MUSICPILOT_SUBSCRIPTION_SCHEDULER_POLL_SECONDS`
- `MUSICPILOT_SUBSCRIPTION_SCHEDULER_DEFAULT_INTERVAL_MINUTES`

订阅自己的调度间隔保存在：

- `subscription.preference_json.schedule_interval_minutes`

若未显式配置，则回退到全局默认值。

## 运行语义

订阅会被视为 due，当且仅当同时满足：

1. `status == active`
2. `mode == scheduled`
3. 当前没有 `running` 状态的 run
4. `now >= baseline + interval`

其中 `baseline` 取值顺序为：

- `last_run_at`
- `updated_at`
- `created_at`

SQLite 返回的 naive datetime 会在 scheduler 内统一归一为 UTC，再参与比较。

## 运行态 smoke 结果

2026-04-05 在临时 SQLite + `TestClient` 运行态下验证：

- 创建 `scheduled` 订阅
- 将 `updated_at` 回拨两分钟
- 等待一个 poll 周期
- 调度器自动执行一次 run

结果：

- scheduler 日志出现 `subscription.scheduler.executed ids=...`
- `GET /api/v1/plugin/musicpilot/subscriptions/{id}/runs`
  - `total = 1`
  - `latest_execution_status = dispatched`
- `subscription.mock = false`
- `runs.mock = false`

这说明当前最小 scheduler 已经能在应用内真实触发一次订阅执行链。

当前默认 mock smoke 下，由于 dispatch 后还没有真实本地源文件，run 会停在：

- `latest_execution_status = dispatched`

当 organize preview 已带出明确 `source_path` 时，同一条执行链会继续自动进入 `apply`。

## 当前边界

- 这是最小应用内 scheduler，不是独立任务系统
- 运行态仍依赖当前 FastAPI 进程常驻
- 当 metadata / discovery / organize 能力继续增强时，scheduler 会自动复用同一条执行链
