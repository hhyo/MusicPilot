# 15. 彻底清理变更说明

> 用途：记录本轮 breaking cleanup 的物理删除项、升级影响和最小升级步骤。

## 15.1 本轮物理删除项

### 数据库列

- `search_jobs.strategy`
- `subscription_runs.dispatch_recommendation`

### 环境变量 / 配置别名

- `MUSICPILOT_HOST_SEARCH_PATH`
- `MUSICPILOT_HOST_DISPATCH_PATH`
- `MUSICPILOT_HOST_ORGANIZE_PREVIEW_PATH`
- `MUSICPILOT_HOST_ORGANIZE_APPLY_PATH`
- `MUSICPILOT_HOST_API_PREFIX`

### 代码兼容分支

- `host_search_title_path or host_search_path`
- `host_download_add_path or host_dispatch_path`
- `host_transfer_name_path or host_organize_preview_path`
- `host_transfer_manual_path or host_organize_apply_path`
- `SearchJob` 写入默认 `strategy="default"` 的旧兼容逻辑

## 15.2 影响范围

- 旧的 `backend/data/musicpilot.db` 不再兼容当前模型结构。
- 旧的本地环境如果还在使用上述别名变量，升级后将不再生效。
- `plugin_runtime` 需要重新打包，避免镜像继续保留旧字段和旧配置名。

## 15.3 升级方式

推荐直接重建本地 SQLite：

```bash
cd /Users/lihuanhuan/PycharmProjects/MusicPilot/backend
python -m app.db_init --rebuild
```

然后重新装配 runtime：

```bash
cd /Users/lihuanhuan/PycharmProjects/MusicPilot
python3 scripts/package_plugin.py
```

## 15.4 最小升级步骤

1. 更新本地环境变量，删除旧别名，只保留当前主名称。
2. 执行 `python -m app.db_init --rebuild` 重建 SQLite。
3. 启动 backend，检查 `/health`、`/api/probe/health`、`/openapi.json`。
4. 重新构建 frontend。
5. 重新执行 `python3 scripts/package_plugin.py`。

## 15.5 当前唯一有效的配置名

- Search title: `MUSICPILOT_HOST_SEARCH_TITLE_PATH`
- Search media: `MUSICPILOT_HOST_SEARCH_MEDIA_PATH`
- Download add: `MUSICPILOT_HOST_DOWNLOAD_ADD_PATH`
- Download media: `MUSICPILOT_HOST_DOWNLOAD_MEDIA_PATH`
- Transfer name: `MUSICPILOT_HOST_TRANSFER_NAME_PATH`
- Transfer manual: `MUSICPILOT_HOST_TRANSFER_MANUAL_PATH`

本文件之后，仓库不再为旧别名提供兼容说明。
