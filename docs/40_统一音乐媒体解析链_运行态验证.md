# 40. 统一音乐媒体解析链运行态验证

## 目标

确认 `MusicMediaInput -> MusicMetaBase -> MusicMediaInfo` 已不只是设计基线，而是已经接管当前版本的 discovery 下钻 detail 主路径，并开始进入下游服务。

## 本轮覆盖范围

- backend 统一媒体解析链 schema / service / API
- discovery 页面到 metadata drawer 的前端主路径
- query builder、search job、candidate scoring 与 host search 对 `MusicMediaInfo` 的消费
- chart_entry 订阅创建对 `MusicMediaInput / MusicMetaBase / MusicMediaInfo` 相关 snapshot 的持久化
- subscription execution 对 `MusicMediaInfo` snapshot 的优先消费，以及对 `MusicMediaInput` snapshot 的补全解析
- organize 上游对 `MusicMediaInfo` snapshot 的识别兜底
- SearchJob 持久化从旧 `query_source_type/query_source_id/metadata_snapshot` 切换到 `music_media_input/music_media_info`
- `plugin_runtime` 打包同步

### 7. 打包产物一致性

校验方式：

- `frontend/dist/index.html` 与 `plugin_runtime/plugins/musicpilot/static/index.html` 逐字比对

结果：

- `index.html`：一致
- `remoteEntry.js`：不做逐字一致要求
  - `plugin_runtime` 版本会经过 `normalize_remote_entry_asset_paths()` 修正宿主嵌套路径问题
  - 同时会发布到 `static/remotes/<hash>/remoteEntry.js`
  - 这属于预期的 runtime packaging 变换，不是产物漂移

## 当前结论

本轮已经确认：

- discovery 条目到 metadata drawer 的主路径已切到 `/media/resolve/detail`
- discovery 产品层已正式输出 `meta_base + recognition_assessment`
- 前端不再依赖 `DiscoveryTarget / direct_id / search_lookup / resolution_hints`
- backend 旧 `/metadata/lookup` 主路径已移除
- RSS / 弱来源 chart entry 订阅创建已接入统一链，并会固化 `MusicMediaInput / MusicMetaBase / MusicRecognitionAssessment / MusicMediaInfo` snapshot
- `subscription_execution` 已会优先消费 `MusicMediaInfo`，并可从 `MusicMediaInput` snapshot 补全正式媒体对象
- `query_builder`、`search_job`、`candidate scoring`、`host search` 与 `organize` 已开始消费 `MusicMediaInfo`
- `plugin_runtime` 已同步到新主链代码和静态产物
