# 41. 插件侧栏导航与独立页面运行态验证

## 目标

验证 MusicPilot 在 MoviePilot v2.9.27 新增的插件导航能力下，已经支持：

- 宿主侧边栏导航项
- `plugin-app` 独立页面路由
- 远程 `AppPage` 组件加载

并确认该能力已同步到本地宿主运行环境。

## 对照的宿主实现原理

本轮对照了 MoviePilot 官方 v2.9.27 的两部分更新：

- 后端：
  - `PluginManager.get_plugin_sidebar_nav()`
  - `GET /api/v1/plugin/sidebar_nav`
- 前端：
  - `/plugin-app/:pluginId/:navKey?`
  - 联邦加载优先级：`AppPage{Pascal(navKey)}` -> `AppPage` -> `Page`

MusicPilot 当前按这个契约接入：

- 插件入口提供 `get_sidebar_nav()`
- 联邦远程暴露 `AppPage`
- `nav_key=main`
- 宿主通过 `/api/v1/plugin/remotes` 获取远程入口

## 关键问题与修复

本轮真实运行态里出现过两个问题：

### 1. `/plugin/sidebar_nav` 返回空对象

根因不是插件未实现导航，而是本地宿主后端进程未重启到带新接口的代码；重启后：

- `PluginManager().get_plugin_sidebar_nav()` 正常返回 `musicpilot/main`
- `GET /api/v1/plugin/sidebar_nav` 正常返回数组

### 2. `plugin-app` 页面提示“无法加载插件全页组件”

根因是 federated `remoteEntry.js` 仍在请求：

- `./assets/__federation_expose_AppPage-*.js`
- `./assets/__federation_expose_Page-*.js`

但我们实际将 remote bundle 发布到了：

- `static/remotes/<hash>/`

修复后：

- `remoteEntry.js` 不再给 `AppPage/Page` chunk 加 `./assets/` 前缀
- 运行时 `get_render_mode()` 也不再按字典序挑选 remote hash，而是按最新 bundle 目录选择
