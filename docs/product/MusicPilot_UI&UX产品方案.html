3. 页面级详细设计

3.1 MusicPilot 首页
定位为音乐业务工作台，不是内容社区首页，也不是播放器首页。
高频入口状态总览低学习成本

页面目标

  • 让用户 1 次进入就找到常用音乐操作。
  • 优先看到待处理任务和最近关注内容。
  • 为榜单、搜索、订阅、下载确认提供快捷入口。

首屏区块

  • 顶部标题区：MusicPilot 名称、消息或任务提醒。
  • 全局搜索框：支持搜歌、搜专辑、搜艺人。
  • 快捷操作：搜索、看榜单、新建订阅、处理待确认。
  • 状态卡：今日新增、待处理、下载中、整理失败。

次级区块

  • 最近搜索
  • 最近订阅
  • 最近新增资源
  • 推荐榜单入口

展示与交互细节

  • 搜索框获得焦点后，优先展示最近搜索和推荐关键词，而不是立即跳转空白页。
  • 快捷操作卡片使用图标 + 一句话说明，点击后直接进入对应页面或打开弹层。
  • 状态卡点击后必须可下钻，例如待确认 8 条点击进入下载确认列表并自动带上状态筛选。
  • 最近订阅区每张卡片展示：对象名、订阅类型、最近执行时间、当前状态、快捷开关。

空状态

新用户进入时，显示去搜索音乐、订阅热门榜单、导入已有目录三个引导入口。

异常状态

后端服务不可用时，只收起动态区块，保留静态导航与重试按钮，避免整页白屏。

埋点建议

搜索框点击率、快捷入口点击率、状态卡下钻率、最近订阅恢复访问率。
3.2 榜单页
榜单页负责发现和批量订阅，不承担全局搜索职责。
平台切换榜单筛选批量订阅

页面结构

  • 顶部平台切换：QQ 音乐 / 网易云 / Bilibili 等。
  • 榜单筛选区：地区、语种、类型、更新周期、排序。
  • 榜单卡片区：宫格或双列卡片。
  • 底部悬浮批量操作栏：勾选后出现。

榜单卡片字段

  • 封面
  • 榜单名称
  • 平台来源
  • 更新时间/刷新频率
  • 当前订阅状态
  • 主按钮：查看详情、订阅

详情页下钻

  • 榜单简介
  • 入榜曲目列表
  • 近几次更新变化
  • Top N 订阅策略
  • 仅增量同步开关

关键交互

  • 切换平台时保留可继承筛选条件，不兼容条件自动清除并提示。
  • 点击订阅时弹出底部抽屉，确认订阅粒度：Top 10 / Top 20 / Top 50 / 全量。
  • 批量勾选榜单后，悬浮操作栏提供批量订阅、批量取消、统一设置更新频率。
  • 榜单详情页中的曲目支持批量加入歌曲订阅，但默认不开启，避免误操作。

空状态

筛选后无结果时，展示清除筛选与切换平台两个主要按钮。

异常状态

平台榜单拉取失败时，保留上次缓存内容并标记数据可能不是最新。

埋点建议

平台切换次数、榜单订阅转化率、Top N 选择分布、详情页曲目下钻率。
3.3 全局搜索页
核心任务是快速定位歌曲、专辑、艺人，并在结果层完成订阅或获取。
结果分段结果直达动作低跳转成本

页面结构

  • 吸顶搜索框
  • 搜索历史与热搜推荐
  • 结果分段：综合 / 歌曲 / 专辑 / 艺人
  • 结果列表
  • 底部加载更多或分页

结果项字段

  • 歌曲：歌名、艺人、专辑、版本、年份
  • 专辑：专辑名、艺人、发行时间、版本信息
  • 艺人：姓名、别名、地区、代表作品数

结果项动作

  • 订阅
  • 获取
  • 查看详情
  • 加入收藏/稍后处理

关键交互

  • 输入期间先提供联想建议，回车后进入标准结果页。
  • 综合结果默认每类展示前几条，并在分组头部提供查看全部。
  • 每条结果应支持直接操作，不要求用户必须进入详情页。
  • 连续搜索时，保留上一个搜索词可快速清除或二次编辑。
  • 对高歧义词，优先提供你是不是要找：歌曲 / 专辑 / 艺人的弱提示，不强制打断。

无结果

提示检查关键词、切换搜索类型、尝试艺人/专辑名，并提供创建手动订阅。

加载状态

使用骨架屏，不使用纯转圈。每类结果可分段完成，先返回先展示。

埋点建议

联想点击率、结果点击率、结果页直接订阅率、直接获取率、无结果率。
3.4 详情页（艺人 / 专辑 / 歌曲）
详情页承担补充理解、启动动作、查看历史的职责。
头部摘要内容分区历史可追溯

头部摘要区

  • 封面/头像
  • 标题与副标题
  • 核心元数据
  • 主按钮：订阅、获取
  • 次按钮：收藏、分享、更多

中部内容区

  • 简介
  • 歌曲列表 / 专辑列表 / 参与作品
  • 版本信息
  • 相关推荐

底部工具区

  • 最近订阅记录
  • 最近获取记录
  • 命中率
  • 失败原因与重试入口

不同实体的差异化要求

  • 艺人页更强调作品时间线、新歌/新专开关、合作曲策略。
  • 专辑页更强调版本差异、发行时间、曲目列表、整专下载策略。
  • 歌曲页更强调版本、音质、别名、是否属于某专辑。

交互细节

作品列表支持单项操作和批量操作；展开版本信息时用折叠区，不额外跳页。

空状态

若简介缺失则隐藏简介区；若无历史记录，展示尚未执行过获取/订阅。

埋点建议

详情页订阅率、详情页获取率、作品列表展开率、版本筛选使用率。
3.5 订阅页
统一管理榜单、歌曲、专辑、艺人四类订阅，核心是看懂当前策略。
分类管理策略可视批量维护

页面结构

  • 顶部统计：全部、启用中、待处理、异常
  • 分类 Tab：榜单 / 歌曲 / 专辑 / 艺人
  • 筛选器：状态、更新时间、策略类型
  • 列表区

订阅卡片字段

  • 对象名称
  • 订阅类型
  • 当前策略摘要
  • 最近执行时间
  • 最近结果
  • 启用开关

快捷动作

  • 编辑策略
  • 立即执行
  • 暂停
  • 删除

策略编辑抽屉建议

  • 榜单订阅：Top N、更新周期、是否仅增量。
  • 歌曲订阅：版本偏好、音质偏好、是否允许现场版/翻唱。
  • 专辑订阅：标准版/豪华版/重制版优先级、是否整专获取。
  • 艺人订阅：新歌、新专、合作曲、回填历史作品、时间范围。

列表交互

左滑或更多菜单提供次级操作；长按或勾选后进入批量模式。

异常状态

若最近执行失败，列表直接展示失败标签，点开可看原因与一键重试。

埋点建议

新建订阅转化率、编辑策略完成率、暂停率、异常重试率。
3.6 获取与下载页
这是最强工具属性页面，必须强调任务状态、候选确认和批量处理效率。
任务列表候选确认批量处理

顶部筛选区

  • 状态：待搜索 / 搜索中 / 待确认 / 已派发 / 已完成 / 失败
  • 来源：订阅触发 / 手动触发 / 榜单触发
  • 时间范围
  • 排序：最近更新 / 优先级 / 失败优先

任务列表字段

  • 对象名
  • 对象类型
  • 触发来源
  • 当前状态
  • 更新时间
  • 可执行动作

候选资源抽屉

  • 站点来源
  • 标题解析结果
  • 音质/格式/体积
  • 匹配分
  • 下载按钮 / 忽略按钮

关键交互

  • 待确认任务点击进入右侧抽屉或底部抽屉，避免跳到新页面导致上下文丢失。
  • 候选资源默认按匹配分排序，但用户可以切换按体积、格式、发布时间排序。
  • 批量模式支持：批量通过、批量忽略、批量重试、批量暂停。
  • 下载完成后，状态自动流转到整理页；若失败则保留失败原因和再次搜索入口。

空状态

没有待处理任务时，强调当前队列已清空，并提供返回订阅页或榜单页的快捷入口。

异常状态

搜索失败和下载失败必须区分展示，分别给出重试搜索和重派下载按钮。

埋点建议

待确认通过率、人工改选率、失败重试率、批量操作使用率。

整理页主要承担命名、归档、标签写入、封面歌词补全和失败处理。
结果可见失败可修复工具属性强

页面结构

  • 顶部统计：成功、失败、处理中

  • 整理结果列表

列表字段

  • 文件/专辑名称
  • 目标路径
  • 命名规则结果
  • 标签写入状态
  • 封面/歌词补全状态

可执行动作

  • 查看详情

  • 修正映射
  • 复制日志

关键交互

  • 失败项直接暴露失败原因摘要，例如命名冲突、标签写入失败、路径不可写。
  • 点击失败项可展开详细日志，但默认不在列表中堆大段文本。
  • 支持多选后批量重试整理。
  • 若封面或歌词补全失败，可单独重新触发，不需要整体重跑。

空状态

暂无整理任务时显示新的下载完成后会自动出现在这里。

异常状态

当目录不可写或规则配置异常时，在页首展示全局警告条，而不是埋在列表中。

埋点建议

整理成功率、单独重试率、失败原因分布、日志展开率。

高保真设计原则

  • 页面背景保持浅色与留白，让音乐封面成为高饱和信息点，而不是整页都变成深色播放器风格。
  • 按钮、激活态、标签、关键状态统一继承宿主紫色体系，不另起新品牌色。
  • 信息密度上遵循“视觉吸引 + 工具效率”双目标：首页和榜单更偏展示，订阅、下载、整理更偏管理。

11. 设计结论

不是重做 UI
MusicPilot 最佳路径是沿用 MoviePilot 的宿主气质，而不是重新设计一套音乐产品视觉系统。
重点在页面效率
真正重要的是搜索、订阅、确认、下载、整理这些关键页面的操作效率与状态可见性。
