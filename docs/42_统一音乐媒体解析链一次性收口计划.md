# 统一音乐媒体解析链一次性收口计划

> 状态：2026-04-12 已完成后端收口。
>
> 完成结果：
> - discovery、detail、search job、subscription、subscription execution、organize 上游识别已全部只通过 `MusicMediaChain`
> - `SearchJobModel`、`SubscriptionModel`、`SubscriptionRunModel`、`OrganizeRecordModel` 已显式持久化统一链对象
> - `/media/prepare`、`/media/resolve`、`/media/resolve/detail` 已成为统一链正式 HTTP 面
> - `/metadata/lookup` 已删除并保持 `404`
> - 后端活跃代码已不再保留 `DiscoveryTarget / resolution_hints / search_lookup` 等旧识别主路径

## 1. 目标

把 MusicPilot 后端里与“音乐实体识别”相关的上层语义一次性收口到唯一主路径：

`MusicMediaInput -> MusicMetaBase -> MusicMediaInfo`

本次计划只处理这条统一链本身，不混入 dashboard、下载工作台、settings profiles 等其他模块建设。

收口完成后的判定标准：

1. discovery、detail、search job、subscription、subscription execution、organize 上游识别全部只通过 `MusicMediaChain`。
2. 统一链相关快照不再散落在 `target_payload_json`、`summary_json`、`raw_payload` 的临时字段里。
3. 旧的过渡态 lookup 语义和来源特判不再作为后端主路径存在。
4. API、持久化、测试、文档都以统一链为唯一基线。

## 2. 当前状态

当前后端已经完成第一轮切换，但仍处于“主干已建立、收尾未完成”的状态。

已完成：

- 核心模型已存在：
  - `MusicMediaInput`
  - `MusicMetaBase`
  - `MusicMediaInfo`
- 核心服务已存在：
  - `MusicMediaInputAdapter`
  - `MusicMetaBaseBuilder`
  - `MusicMediaRecognizer`
  - `MusicMediaInfoHydrator`
  - `MusicMediaChain`
- 已接入统一链的场景：
  - discovery 准备阶段
  - `/media/resolve`
  - `/media/resolve/detail`
  - metadata detail 路由
  - search job 创建
  - query builder
  - subscription create
  - subscription execution
  - organize 上游 hydrate

仍残留的过渡态问题：

1. 统一链契约还不够硬：
   - `MusicRecognitionAssessment.state` 仍是自由字符串
   - `source_kind`、`match_strategy` 等关键字段还未类型化
2. detail 路由仍带 provider 假设：
   - `backend/app/api/routes/search.py` 里仍写死 `provider="musicbrainz"`
3. 持久化仍有明显过渡痕迹：
   - `SubscriptionModel.target_payload_json`
   - `SubscriptionRunModel.summary_json`
   - `OrganizeRecordModel.raw_payload`
   里面仍混有统一链快照
4. 业务服务虽然已经改用统一链，但仍有部分“从旧快照反推输入”的补桥逻辑
5. `MetadataService` 仍同时承担 provider detail 和本地 seed detail 语义，和统一链的职责边界还不够清晰

## 4. 目标状态

### 4.1 统一链模型

统一链只保留以下正式模型：

- `MusicMediaInput`
- `MusicMetaBase`
- `MusicMediaInfo`
- `MusicRecognitionAssessment`
- `MusicPrepareResponse`
- `MusicResolveResponse`
- `MusicResolveDetailResponse`

并明确三层关系：

- `MusicMediaInput`：原始线索输入
- `MusicMetaBase`：统一归一化后的中间元数据
- `MusicMediaInfo`：识别后的正式音乐实体

### 4.2 统一链 API

统一链对外 HTTP 面固定为：

- `POST /media/prepare`
- `POST /media/resolve`
- `POST /media/resolve/detail`

语义分别是：

- `/media/prepare`
  - `MusicMediaInput -> MusicMetaBase + MusicRecognitionAssessment`
- `/media/resolve`
  - `MusicMediaInput -> MusicMetaBase + MusicRecognitionAssessment + MusicMediaInfo`
- `/media/resolve/detail`
  - `MusicMediaInput -> MusicMetaBase + MusicRecognitionAssessment + MusicMediaInfo + MetadataDetail`

`/metadata/search` 保留为 provider 搜索入口。  
`/metadata/artists|albums|tracks/{id}` 保留为面向产品语义的 detail 路由，但内部必须只是统一链 wrapper，不再带任何 provider 写死假设。

### 4.3 统一链持久化

统一链相关快照只允许落在显式字段，不再混进业务杂项 JSON。

目标调整：

- `SearchJobModel`
  - 保留：
    - `music_media_input`
    - `music_meta_base`
    - `music_media_info`
  - 新增：
    - `music_recognition_assessment`
  - 清理：
    - 从 `summary_json` 中去掉统一链快照

- `SubscriptionModel`
  - 新增：
    - `music_media_input`
    - `music_meta_base`
    - `music_recognition_assessment`
    - `music_media_info`
  - 保留：
    - `target_payload_json` 仅存业务目标上下文，不再承载统一链快照

- `SubscriptionRunModel`
  - 新增：
    - `music_media_input`
    - `music_meta_base`
    - `music_recognition_assessment`
    - `music_media_info`
  - 保留：
    - `summary_json` 仅存执行摘要，不再承载统一链快照

- `OrganizeRecordModel`
  - 新增：
    - `music_media_info`
  - 视需要新增：
    - `music_meta_base`
  - `raw_payload` 只保留 organize 运行态结果，不再承担统一链主快照职责

本次接受 breaking change，数据库直接重建，不做兼容迁移。

## 5. 模块收口方案

### 5.1 Schema 层定稿

涉及文件：

- `backend/app/schemas/music_media.py`
- `backend/app/schemas/orchestration.py`
- `backend/app/schemas/acquisition.py`

处理内容：

1. 把 `MusicRecognitionAssessment.state` 改成正式枚举
   - 建议：`direct / ready / insufficient / failed`
2. 把 `source_kind` 从自由字符串收成正式枚举
3. 把 `match_strategy` 从自由字符串收成正式枚举
4. 明确 `MusicPrepareResponse` 进入正式公开契约
5. 去掉 orchestration/acquisition 中仍然把统一链视为“附加字段”的表述，改成正式依赖字段

### 5.2 Chain 服务层定稿

涉及文件：

- `backend/app/services/music_media_chain.py`
- `backend/app/services/music_media_input_adapter.py`
- `backend/app/services/music_meta_base_builder.py`
- `backend/app/services/music_media_recognizer.py`
- `backend/app/services/music_media_info_hydrator.py`

处理内容：

1. `MusicMediaChain` 成为唯一公开入口
2. 所有场景服务只允许调用 `MusicMediaChain` 的公开方法
3. 不允许业务服务直接碰：
   - `input_adapter`
   - `base_builder`
   - `recognizer`
   - `hydrator`
4. recognizer 内部保留：
   - 强引用直达
   - 弱线索识别
   但这些路径不再外露为业务模式
5. 收紧 provider 语义，去掉 detail 路由里的 `musicbrainz` 写死

### 5.3 Metadata 边界重申

涉及文件：

- `backend/app/services/metadata.py`
- `backend/app/api/routes/search.py`

处理内容：

1. `MetadataService` 只负责：
   - metadata search
   - provider detail / seed detail
2. 统一链负责：
   - 输入构造
   - 中间元数据构造
   - 实体识别
3. metadata detail 路由不再自己理解 provider，只通过统一链和 active provider 适配

### 5.4 Search Job 收口

涉及文件：

- `backend/app/services/search_job.py`
- `backend/app/models/acquisition.py`
- `backend/app/repositories/acquisition.py`
- `backend/app/schemas/acquisition.py`

处理内容：

1. SearchJob 显式持久化 `music_recognition_assessment`
2. `summary_json` 不再混放统一链快照
3. SearchJob 全流程只消费：
   - `MusicMediaInput`
   - `MusicMetaBase`
   - `MusicMediaInfo`
4. query build 上游不再反向构造旧识别上下文

### 5.5 Subscription 收口

涉及文件：

- `backend/app/services/subscriptions.py`
- `backend/app/services/subscription_execution.py`
- `backend/app/models/orchestration.py`
- `backend/app/repositories/orchestration.py`
- `backend/app/schemas/orchestration.py`

处理内容：

1. 创建订阅时，把统一链快照写入显式字段，不再塞进 `target_payload_json`
2. 执行订阅时，优先只从显式字段读取统一链快照
3. `target_payload_json` 只保留：
   - chart/source/rank
   - 原始业务目标上下文
4. run 详情里展示统一链结果时，从正式字段读取，不再从 summary 临时字段反解

### 5.6 Organize 收口

涉及文件：

- `backend/app/services/organize.py`
- `backend/app/models/orchestration.py`
- `backend/app/repositories/orchestration.py`

处理内容：

1. organize 上游 hydrate 优先只读正式 `music_media_info`
2. 去掉从 candidate/binding `raw_payload` 里找统一链快照的主逻辑
3. `raw_payload` 退回为 organize 结果与 handoff 运行态数据

### 5.7 Discovery 收口

涉及文件：

- `backend/app/services/discovery.py`
- `backend/app/schemas/orchestration.py`
- `backend/app/services/charts.py`

处理内容：

1. discovery 输出继续保留：
   - `media_input`
   - `meta_base`
   - `recognition_assessment`
2. 不再引入任何局部 lookup 桥接语义
3. chart entry -> subscription 时只走统一链正式对象
