# MusicPilot 需求保留版技术设计文档

> 基于 MoviePilot 插件系统的独立音乐业务插件方案

> 版本：v9  ·  产出日期：2026-04-01  ·  文档定位：需求驱动 + 插件约束落地

> 文档说明
> 本版文档保留最初业务需求，先回答“MusicPilot 必须实现什么”，再回答“在 MoviePilot 插件系统下如何落地”。插件系统分析被下沉为实现约束，而不是替代原始需求。

## 1. 项目背景与原始需求

本项目起点不是“做一个通用音乐系统”，而是基于 MoviePilot 现有插件体系扩展出一个可与影视能力长期共存的 MusicPilot。原始需求必须完整保留，后续所有技术设计都只是在宿主插件边界下做实现收敛。

### 1.1 原始业务目标

- 基于 MoviePilot 插件系统设计 MusicPilot，并以独立插件入口方式接入宿主。

- 不侵入原有影视代码与主页面逻辑，音乐能力与电影 / 电视剧能力平行共存。

- 实现完整音乐业务闭环：发现 -> 搜索 -> 订阅 -> PT 获取 -> 下载 -> 整理入库。

- 支持音乐榜单、音乐媒体实体、音乐订阅对象和音乐资源获取全流程。

### 1.2 已确认的需求边界

- 榜单模块不承担全局检索职责，只负责展示、筛选和订阅。

- 全局检索必须支持音乐媒体维度：艺人 Artist、歌曲 Track、专辑 Album。

- 订阅类型必须扩展为：榜单、歌曲、专辑、艺人四类。

- 需要支持基于元信息主动搜索 PT 站点，并在命中后触发自动下载编排。

- 项目开发目录可以工程化组织，但面向 MoviePilot 的最终发布产物必须遵循插件目录规范，并通过 Release 包分发。

### 1.3 非目标

- 不把音乐能力硬塞进原有影视推荐页、搜索页或订阅页。

- 不重做 MoviePilot 已经具备的 PT 多站点并行搜索、基础过滤和下载器派发底座。

- 不在 V1 阶段追求推荐算法、社交热度模型或跨平台复杂版权处理。

## 2. MoviePilot 插件系统分析：实现约束而非需求替代

MoviePilot 插件体系决定了 MusicPilot 最适合做成“独立插件入口 + 宿主能力复用 + 音乐域补强”的方案。它限制的是嵌入方式，不改变原始业务目标。

### 2.1 插件系统可直接承载的能力

- 插件页面 / 远程组件：适合承载 MusicPilot 的独立前端页面体系。

- 插件 API：适合提供音乐榜单、搜索、订阅、获取与设置接口。

- 插件服务与定时任务：适合承载榜单刷新、订阅扫描、主动搜索与整理任务。

- 宿主公共能力：可复用站点配置、PT 索引器、下载器、通知、调度、用户与权限体系。

### 2.2 插件系统对方案的关键约束

- 页面应新增，不替换：音乐能力通过独立入口进入，不改原影视页面主流程。

- 接口应独立命名空间：统一放在 /api/v1/plugin/musicpilot/ 下。

- 数据应独立建模：音乐实体与订阅不复用电影 / 电视剧表语义。

- 扩展优先复用宿主底座，避免重复实现已有 PT 搜索与下载编排基础设施。

## 3. 总体方案：独立插件入口 + 宿主能力复用 + 音乐域补强

### 3.1 目标形态

MusicPilot 不是独立站点，也不是替换 MoviePilot 的前端壳，而是宿主内的独立音乐业务插件。宿主继续承载用户、权限、通知、下载器、站点与调度等公共能力；MusicPilot 负责音乐域的业务闭环。

### 3.2 页面边界

- 榜单页：展示、筛选、订阅。

- 搜索页：歌曲 / 专辑 / 艺人检索，以及从实体进入 PT 获取。

- 订阅页：榜单、歌曲、专辑、艺人四类订阅对象管理。

- 下载页：搜索任务、匹配结果、人工确认、下载绑定与状态跟踪。

- 整理页：整理日志、目录映射、标签写入、异常重试。

## 4. 业务架构设计

### 4.1 榜单链路

- 榜单源：QQ 音乐、网易云音乐、Bilibili 等榜单提供方。

- 榜单能力：榜单展示、平台筛选、地区 / 风格筛选、Top N 订阅、增量订阅。

- 榜单命中后不直接下载，而是转换为 Track / Album 目标后进入获取链路。

### 4.2 全局检索链路

- 统一搜索入口支持 Artist / Track / Album 三类实体。

- 搜索结果支持类型切换、详情页、直接订阅和进入 PT 获取。

- 实体详情页承担“元信息确认 + 资源获取触发”的中枢作用。

### 4.3 订阅链路

- 榜单订阅：订阅榜单或榜单过滤结果。

- 歌曲订阅：围绕单曲名称、艺人、版本偏好和音质偏好。

- 专辑订阅：围绕整专、版本、首发 / 重制 / Deluxe 策略。

- 艺人订阅：围绕新歌、新专、合作曲、历史作品回填策略。

### 4.4 获取与整理链路

- 获取层根据音乐元信息主动搜索 PT 站点。

- 匹配层对候选资源执行音乐域评分、过滤和排序。

- 决策层判定自动下载 / 待确认 / 拒绝。

- 下载完成后进入音乐整理、标签写入、封面歌词补充与媒体库刷新。

## 5. 宿主复用与 MusicPilot 独立实现边界

| 能力域 | 处理方式 | 说明 |
| --- | --- | --- |
| PT 多站点并行搜索 | 复用宿主 | 沿用宿主 SearchChain 的并发搜索、站点选择与结果汇聚底座。 |
| 单站点 parser / spider | 复用宿主 | 避免插件重复维护大量 PT 站点适配。 |
| 基础过滤 / 去重 / 基础排序 | 复用宿主 | 复用 include / exclude / size 与站点优先级、做种数排序。 |
| 下载器派发 | 复用宿主 | 继续使用宿主已有下载器接入与任务管理。 |
| 音乐查询构建 | 独立实现 | 根据 Artist / Album / Track 生成中英文、多版本、多音质搜索词。 |
| 音乐匹配评分 | 独立实现 | 围绕艺人、专辑、歌曲名、年份、版本、音质做领域判定。 |
| 音乐过滤扩展 | 独立实现 | 补充 FLAC、APE、WAV、Hi-Res、整专 / 单曲、Live / Remaster 规则。 |
| 自动下载决策 | 独立实现 | 输出自动下载、待确认、拒绝及原因。 |
| 音乐整理规则 | 独立实现 | 专辑目录、多碟、标签、封面、歌词与媒体库刷新。 |

## 8. PT 主动搜索与自动下载编排

这部分保留原始需求，但按插件系统能力重新落地：不重写宿主 PT 搜索底座，而是在宿主搜索结果之上补音乐域判定逻辑。

### 8.1 查询构建

- Album 示例：周杰伦 太阳之子 2026 FLAC / Jay Chou Children Of The Sun 2026 FLAC。

- Track 示例：周杰伦 太阳之子 single FLAC / Jay Chou Children Of The Sun track FLAC。

- 支持中英文名、别名、年份、版本限定、音质限定、过滤词。

### 8.2 推荐时序

- A. 手动触发或订阅命中 -> 生成 SearchJob。

- B. MusicQueryBuilder 生成多组搜索词。

- C. 调用宿主现有并行搜索链路 -> 返回 TorrentInfo 列表。

- D. MusicMatchEngine / MusicRanker 执行音乐匹配、过滤和重排序。

- E. DecisionEngine 判定自动下载、待确认或拒绝。

- F. 自动下载时调用宿主 download；待确认时进入插件下载页。

- G. 下载完成后触发 MusicOrganizer。

### 8.3 自动下载决策

- 自动下载：标题高匹配、艺人 / 专辑一致、音质命中、版本可信、站点质量达标。

- 待确认：多候选并存、可能命中合集 / 特别版、命中分数高但不绝对。

- 拒绝：低分、误匹配、命中黑名单、格式不符合策略。

## 9. 数据模型设计

- Artist / Album / Track：音乐元信息主实体。

- Chart / ChartEntry：榜单与榜单条目。

- Subscription：chart / track / album / artist 四类订阅。

- SearchJob / SearchResult：主动搜索任务与站点返回结果。

- MatchRecord：匹配分数、判定结果与理由。

- DownloadBinding：下载器任务与搜索结果绑定。

- LibraryItem：整理入库后的音乐馆藏映射。

## 10. 工程结构与 Release 发布

开发目录可以工程化组织，但最终发布给 MoviePilot 的插件产物必须符合插件目录规范。

### 10.1 推荐仓库结构

```text
repo/
  frontend/
  backend/
  docs/
  scripts/
  build/

  package.json
  plugins/
    musicpilot/
      __init__.py
      requirements.txt
      static/
      manifest/
```

### 10.2 发布原则

- 开发阶段：在 frontend / backend / docs / scripts 下进行正常工程化开发。

- 构建阶段：将插件代码、静态资源、requirements、版本号整理到标准插件产物目录。

- 发布阶段：通过 GitHub Release 包分发；Release 只优化分发效率，不替代插件仓库元信息规范。

## 11. 实施分期建议

| 阶段 | 范围 | 目标 |

| MVP | 独立插件入口、榜单展示、Artist / Track / Album 检索、手动 PT 搜索与手动下载 | 先打通从实体检索到资源获取的闭环。 |

## 12. 最终技术决策

| 决策项 | 最终结论 |
| --- | --- |
| 需求主线 | 完整保留原始音乐业务需求，不因插件系统分析而裁剪目标。 |
| 入口方案 | 采用独立 MusicPilot 插件入口，不侵入原影视页面。 |
| 实现边界 | 宿主负责公共能力承载，MusicPilot 负责音乐业务闭环。 |
| PT 获取 | 复用宿主并行搜索、基础过滤和下载器派发；插件补音乐查询、判定与决策。 |
| 工程与发布 | 开发目录工程化，发布产物遵循 MoviePilot 插件目录规范，并通过 Release 包分发。 |
