# 25. 真实插件加载验证

## 目标

验证 MusicPilot 当前 `organize apply` 正式化后的实现，是否已经满足以下两点：

1. 能被 MoviePilot 插件管理器真实加载并注册插件 API。
2. 能在宿主插件进程内直接调用宿主 file/storage runtime 执行音乐文件整理的底层文件操作。
3. 能通过宿主真实插件 API 完成一次最小 `organize/apply` 闭环，并保持 organize record 回写。

本次验证不扩大到完整音乐样本验收，只验证“插件加载链”“插件内执行链”和“最小插件 API 闭环”。

## 验证环境

- MusicPilot 工作区：`/Users/lihuanhuan/PycharmProjects/MusicPilot`
- 宿主源码：`/Users/lihuanhuan/PycharmProjects/MoviePilotPkg/MoviePilot`
- 宿主插件参考：`/Users/lihuanhuan/PycharmProjects/MoviePilotPkg/MoviePilot-Plugins`
- 宿主运行配置：`CONFIG_DIR=/Users/lihuanhuan/PycharmProjects/MoviePilotPkg/MoviePilot/config-dev`

## 本次最小接入

为避免继续依赖开发期 bridge，本次验证使用了两项最小接入：

1. `backend/app/__init__.py` 增加最小 MoviePilot 插件入口类 `musicpilot(_PluginBase)`。
2. 将 `plugin_runtime/plugins/musicpilot` 同步到宿主本地 `app/plugins/musicpilot`，并将 `musicpilot` 写入宿主本地 `UserInstalledPlugins`。

说明：

- 这是本地验证接入，不是插件市场安装流程验证。
- 未修改 MoviePilot 参考源码逻辑，只在本地宿主仓库增加了待验证插件目录。
- `musicpilot.init_plugin()` 现在会在宿主插件初始化时主动 bootstrap MusicPilot 自己的 SQLite schema，避免 `get_api()` 可用但业务路由缺表。

## 验证结果

### 1. 真实插件加载链通过

在宿主真实 startup 生命周期下：

- `PluginManager().start()` 成功加载 `musicpilot`
- 宿主日志出现：`加载插件：musicpilot 版本：0.1.0`
- 宿主 app 中实际注册了 `37` 条 `/api/v1/plugin/musicpilot/*` 路由
- `GET /api/v1/plugin/musicpilot/health` 返回 `200` 且 `success=true`

这说明：

- 当前 `plugin_runtime/plugins/musicpilot` 已具备被宿主插件管理器真实加载的最小入口
- `get_api()` 注册链路已经打通

### 2. 真实插件进程内文件执行链通过

在宿主解释器中直接调用：

- `app.plugins.musicpilot.adapters.host_storage_runtime.HostStorageRuntimeBridge.transfer_file(...)`

执行单文件 `local -> local copy` smoke check，结果：

- `success=true`
- `organize_status=applied`
- 目标文件实际存在，大小与源文件一致

这说明：

- 当前 `HostStorageRuntimeBridge` 已不再依赖 `_resolve_host_root/subprocess/sys.path`
- 它能够在宿主插件进程内直接复用宿主 file/storage runtime

### 3. 真实插件 API 最小 `organize/apply` 闭环通过

在宿主真实插件加载链下：

1. 使用 `app.plugins.musicpilot.core.db.SessionLocal` 在插件自己的 SQLite 中写入最小 `SearchJob / SearchCandidate / OrganizeRecord`。
2. 准备本地单文件源文件和已存在的目标目录。
3. 通过宿主 `TestClient` 调用：
   - `POST /api/v1/plugin/musicpilot/organize/apply`
   - `GET /api/v1/plugin/musicpilot/organize/jobs/{id}`

结果：

- `POST /api/v1/plugin/musicpilot/organize/apply` 返回 `200`
- `code=ORGANIZE_APPLY_OK`
- `data.organize_status=applied`
- `data.organize_backend=host`
- `data.integration_point=RealOrganizeAdapter.apply.music_storage_runtime_transfer`
- organize record detail 可回看，状态仍为 `applied`
- 目标文件实际存在，大小与源文件一致

这说明：

- MusicPilot 自己的插件 SQLite 已在宿主插件初始化时完成 schema bootstrap
- 新的音乐 `apply` 路径已经能通过宿主真实插件 API 走到实际文件执行并回写成功结果

## 当前结论

当前可以确认：

1. MusicPilot 已经从“开发期源码 bridge”进入“真实宿主插件加载 + 宿主插件进程内执行”状态。
2. `organize apply` 的正式化方向成立。
3. 真实宿主插件 API 的最小 `organize/apply` 闭环已通过。

当前仍未覆盖的内容：

- 通过宿主真实插件 API 完整执行一次 `preview -> apply` 的连续业务闭环
- 基于真实音乐元数据恢复与路径规划的成功样例验收

这两个点仍属于后续业务级验证，不影响本次“正式插件加载验证”结论。
