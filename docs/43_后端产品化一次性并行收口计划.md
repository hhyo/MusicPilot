# 后端产品化一次性并行收口计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐项落地。本文按并行工作流组织，不再按单线顺序推进。

**Goal:** 一次性补齐 MusicPilot 后端剩余的产品化能力，把当前“架构已完成、主链可跑”的状态提升为“具备完整管理动作、可观测性、恢复能力和更稳定产品体验”的状态。

**Architecture:** 统一音乐媒体解析链保持为唯一上层识别主路径，所有新增后端能力都围绕现有 `MusicMediaInput -> MusicMetaBase -> MusicMediaInfo` 展开，不再引入新的中间语义。执行方式按 8 条并行工作流推进，所有工作流最终汇总到统一的状态机、诊断视图和验证矩阵。

**Tech Stack:** FastAPI、SQLAlchemy、SQLite、Pydantic v2、宿主 downloader/runtime adapters、plugin_runtime backend mirror、unittest

---

## 范围与完成定义

### 本轮只做

- metadata / discovery 命中质量收口
- discovery 生命周期与 source 健康状态
- SearchJob / candidate / dispatch / handoff 管理动作
- downloads workspace 产品化 API
- subscription scheduler 产品化
- organize workspace 产品化
- dashboard / diagnostics / probe 收口
- 文档、测试、打包、runtime mirror 同步

### 本轮不做

- 新前端实现
- 新 metadata provider
- 新榜单源
- 新数据库体系
- 宿主代码改造

### 完成定义

只有同时满足以下条件，这轮才算完成：

1. metadata / discovery 命中质量有正式回归样本集，且所有新增回归测试通过。
2. discovery、downloads、jobs、subscriptions、organize 都有完整的列表/详情/重试/确认/恢复类后端动作。
3. dashboard 不再只是计数摘要，而能表达 provider、scheduler、handeoff、organize、discovery 的运行态。
4. probe 中仍可保留 `unverified/degraded`，但主业务 API 中不再以 placeholder 语义充当“未完成补丁位”。
5. backend 全量测试、关键定向测试、plugin_runtime 打包全部通过。
6. `README.md`、`backend/README.md`、路线文档同步到最新真实状态。
